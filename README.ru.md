# CC-Autocraft

[English](README.md) | **Русский**

Склад и автокрафт на CC: Tweaked (Minecraft 1.21.1, NeoForge) для Create и GregTech CEu: склад на монитор, кодирование рецептов тестовым крафтом, дерево крафта, очередь заказов, черепашки и машины. Встроенные моды: clipboard для Create, платы и тиры для GregTech; можно писать свои (см. [MODS.md](MODS.md)). Большинство машин других модов тоже работают — всё, у чего один инвентарь. В папке [CC-Autocraft_Mod](CC-Autocraft_Mod) — аддон для EMI/JEI, который выкладывает рецепт в бочку-кодировщик.

## Установка
Одной командой в игре — на ПК склада и на черепашке (черепашку установщик узнаёт сам):
```
wget run https://raw.githubusercontent.com/Asd1if/CC-Autocraft/main/install.lua
```
Обновление — та же команда: она заменяет `system/` и не трогает `config.lua`, `data/` и `mods/`. Вручную: содержимое `Computer/` на ПК, `Turtle/` на черепашку.

Файлы на ПК:
```
startup.lua      сама программа (запускается при загрузке)
config.lua       настройки; создаётся из system/default/config.lua при первом запуске
data/            рецепты, названия, очередь заказов, лог, multiblock.json
mods/            свои моды
system/
  default/       шаблоны config.lua и multiblock.json
  core/          индекс склада, монитор, сеть, планировщик задач, API и загрузчик модов
  craft/         рецепты, расчёт крафта, очередь заказов, кодировщик рецептов
  mods/          встроенные моды: create.lua, gtceu.lua
  utils/         форматирование, лог, сообщения в терминал
```
- Старая установка переносится сама при первом запуске: `data/config.lua` становится `config.lua`, старые `main.lua`, `modules/`, `defaults/` удаляет установщик
- При каждом сохранении рецептов прошлая версия остаётся в `data/recipes.json.bak`; если `recipes.json` пропал, рецепты загрузятся из неё

## Подключение
- ПК: проводной модем к хранилищам, танкам, бочке-кодировщику, машинам и черепашке; монитор
- Черепашка: верстак и проводной модем в той же сети (кольцо модема должно гореть красным). Сама объявляет себя, настраивать ничего не нужно
- Команды черепашке идут по тому же кабелю (rednet работает и по проводным модемам). Беспроводные модемы не нужны; если они есть, сообщения пойдут и по ним
- Если ответ не пришёл за 3 с, ПК повторяет запрос с тем же id; черепашка на повтор отвечает сохранённым ответом и не крафтит второй раз

## config.lua (на ПК)
Lua-таблица, разбитая на блоки линиями `-- ————`. Ключи:

| Ключ | Что |
|---|---|
| `main_monitor` | основной монитор; `nil` — самый большой |
| `fluid_monitor` | маленький монитор танков кодировки; `nil` — любой другой монитор, нет — без панели |
| `main_TextScale`, `fluid_TextScale` | масштаб текста мониторов (0.5 — мельче, влезает больше) |
| `clipboard_reader` | Block Reader перед clipboard Create; `nil` — первый найденный |
| `clipboard_skip_checked` | строки clipboard с галочкой не заказываются |
| `rednet_modem` | модем для команд черепашкам; `nil` — все модемы (хватает проводного) |
| `debug_mode` | полный лог в `data/autocraft.log`; иначе только предупреждения и ошибки |
| `craft_timeout` | сколько секунд машина может простаивать, пока заказ не упадёт |
| `batch` | крафтов за раз: в один turtle.craft или загрузка машины наперёд |
| `restock_interval` | как часто проверять автопополнение, с |
| `rescan` | период полного пересканирования склада, с |
| `storage`, `tanks` | хранилища и танки склада: тип (`create:item_vault`) или точные имена |
| `exclude` | имена, которые подходят под списки выше, но складом не являются |
| `craft_storage`, `craft_tanks` | склад крафта для идущих заказов (точные имена); пусто — выключено |
| `encoder`, `recipe_tanks` | бочка-кодировщик и её танки |
| `pools` | пулы одинаковых машин, см. ниже |
| `restock` | `[предмет] = минимум`, см. ниже |
| `substitutes` | взаимозаменяемые предметы, см. ниже |
| `mods_disabled` | выключенные моды, например `{ "gtceu" }` |
| `gtceu_tier_up` | рецепт GregTech с LV-машины может идти на MV, HV... (по умолчанию `true`) |
| `gtceu_chips` | дополнительные хеши плат: `["<hash>"] = номер` |

В списках периферий можно указать тип (`create:item_vault` — все `create:item_vault_N`) или точное имя. Старые имена ключей (`monitor`, `encoder_monitor`, `text_scale`, `modem`, `debug`) тоже читаются.

Ключи, которых нет в `config.lua`, берутся из `system/default/config.lua` — так новые настройки после обновления работают сразу. Значения в `config.lua` главнее: менять настройки нужно там. Старый `data/config.json` тоже читается, если `config.lua` нет.

### Склад крафта
`craft_storage = { "create:item_vault_2" }` (и `craft_tanks` для жидкостей) — отдельные хранилища для идущих заказов:
- имена отсюда исключаются из основного склада, даже если `storage` задан типом;
- при старте заказа всё, что он берёт со склада, переносится сюда, промежуточные предметы тоже кладутся сюда — руками их не забрать;
- готовый результат последнего шага идёт в основной склад;
- когда ни одного заказа нет (и при запуске ПК), всё оставшееся возвращается в основной склад;
- в списке на мониторе склад крафта не показывается, но для расчёта крафта учитывается.

### Пулы машин
```lua
pools = { panel = { "create:mechanical_press_0", "create:mechanical_press_1" } },
```
Машины пула пропадают из списка в ADD, вместо них пункт **Pool → panel**. Рецепт тестируется на первой машине, при крафте шаг делится поровну между свободными машинами пула. Можно указывать и мультиблоки из `multiblock.json`.

### Взаимозаменяемые предметы
```lua
substitutes = {
  planks = { "minecraft:oak_planks", "minecraft:spruce_planks", ... },
  coal   = { "minecraft:coal", "minecraft:charcoal" },
  copper = { "minecraft:copper_ingot", "othermod:copper_ingot" },  -- своя группа
},
```
Любой предмет группы подходит вместо любого другого во входах рецептов, сначала берётся вид, которого больше на складе (в дереве — `Any planks`). Работает сразу и для уже сохранённых рецептов. Готовые группы: доски, деревянные плиты, булыжник, уголь. Если результат называет вид предмета, замены нет: дубовой плите нужны дубовые доски, а сундук делается из любых.

### Автопополнение
```lua
restock = { ["create:andesite_alloy"] = 256 },
restock_interval = 30,
```
Когда заказов нет, раз в `restock_interval` секунд первый предмет ниже минимума заказывается — сколько хватает ресурсов.

### GregTech (мод gtceu)
- **Платы (Chip ID)**: программная плата кладётся во входную шину/инвентарь машины. Рецепт запоминает плату машины, на которой его тестировали, и все машины того же типа с той же платой работают как пул сами, без настройки. Плату автокрафт из машины никогда не забирает.
- **Тиры**: рецепт, записанный на LV, идёт и на MV, HV... того же типа с той же платой (`gtceu_tier_up = false` — выключить). Сначала машина теста, потом младшие тиры.
- В меню ADD рядом с машиной видны тир и плата: `[ID-3] LV c5`.

## data/multiblock.json
```json
{
  "mixer_line": {
    "input_item": "create:depot_1",
    "output_item": "create:depot_2",
    "input_fluid": "create:fluid_tank_4",
    "output_fluid": "create:fluid_tank_5"
  }
}
```
Обязателен только `input_item`. Без выходов результат ищется во входном блоке.

## Монитор
- Поиск: нажать **S** на клавиатуре ПК и ввести текст в терминале (часть названия или id). Enter без текста — показать всё. Строка «Search: …» над списком сбрасывает поиск по нажатию
- Очередь заказов — до 3 строк над списком: зелёный — готово (10 с), жёлтый — крафтится сейчас, оранжевый — следующий, красный — после него. `+` перед названием — заказ автопополнения. Заказы выполняются по одному
- Нажать на строку очереди или на полосу прогресса — дерево этого заказа (а не пересчёт выбранного предмета)
- **Q** на клавиатуре ПК — отменить текущий заказ (или первый в очереди): шаги останавливаются, резерв снимается, всё из машин и склада крафта возвращается на склад
- Сообщения о заказах (поставлен, готов, не хватает, упал) — в терминале ПК рамками, нехватка в виде `id > количество`
- Незавершённые заказы сохраняются в `data/jobs.lua` и после перезапуска ПК планируются заново от того, что уже есть на складе
- Нажать на предмет — слева появится дерево крафта. `0/4 r3` — ещё 3 есть на складе, но их держат заказы в очереди или в работе
- Заказ всегда крафтит заказанный предмет, даже если он есть на складе (компоненты берутся со склада). Жидкости и предметы без рецепта берутся со склада
- `< << ][ >> >` — −1, −10, заказ, +10, +1. `[N]` — максимум возможного
- У выбранного предмета с рецептом `+` в списке становится красным `-`: первое нажатие спрашивает, второе в течение 5 с удаляет рецепт, по которому строится дерево. Если рецептов несколько, его место займёт следующий
- Жидкости: счётчик начинается с 1B и шагает по 100 mB / 1B. Заказанная жидкость (со склада или скрафченная) наливается в танки кодировки: сначала в танк с той же жидкостью, потом в пустой. Не влезло — остаток на складе, сообщение в терминале
- Иконки: сортировка (по количеству или по возможности крафта), предметы/жидкости, страницы
- `[Clip]` справа внизу (мод create): читает clipboard Create (Material Checklist пушки схем) через Block Reader из Advanced Peripherals. Дерево строится на весь список, счётчик умножает его, `][` заказывает
- ADD заодно ищет новые подключённые машины. Turtle / Machine / Multiblock → мод → машина → id → тестовый крафт. Если в танках рецепта есть жидкости, количество спрашивается в терминале компьютера: `water: 4B > 250` — число в mB, `1b` = 1000, Enter — пропустить жидкость

## Монитор танков (второй, хватит 1x1)
Ставится рядом с кодировщиком, масштаб текста 0.5 по умолчанию (15x10 символов). Строка на танк: `[1]> Water:40mB`, название в цвете жидкости. Нажатие на строку — слить этот танк в склад, оранжевая полоса `All > storage` внизу — слить все. Обновляется раз в 2 с и при каждом пересканировании склада. В конфиге `fluid_monitor` (nil — любой монитор, кроме основного) и `fluid_TextScale`. Если `main_monitor = nil`, основным считается самый большой монитор.

## Если что-то упало
Основные циклы ПК (экран, сеть, склад, очередь, монитор танков) при ошибке перезапускаются сами (не больше 5 раз в минуту). Ошибка пишется в `data/autocraft.log` вместе со стеком — пришлите этот кусок лога.
